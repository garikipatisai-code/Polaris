# Polaris Roadmap — M3.5 → M7

> **Status: scope sketch, NOT a committed plan.** Day estimates were aggregated from 8 research subagents that didn't have repo references and didn't measure the actual model. Each "N days" line is an agent's guess; expect 2-3× in practice based on the project's history of arch-nemesis follow-up rounds. The Linux-box "gates" are decorative — they need explicit success criteria before they can be honestly called gates. We're starting M3.5 (M3-debt-cleanup) and re-planning at each milestone closure rather than committing to this whole sequence.

> **Honest reframe of M3.5:** the items grouped under M3.5 below are *prerequisites that should have shipped with the M3 backend swarm* — safety floor, KV-cache prompt restructure, telemetry, PII filter, `backendDOMNodeId` propagation. Calling it "Foundation" overstates it. It's atonement work, scoped tight, that unblocks future action tools.

> Milestone roadmap synthesizing the 8 research streams (`docs/research/streamN-*.md`) and the cross-cutting summary (`docs/research/SUMMARY.md`).
>
> **Goal:** local-first agentic browser that beats Comet within the Phase-1 use case (cross-retailer shopping deal hunter), running entirely on consumer hardware.
>
> **Estimating convention:** "1 day" = 1 focused engineering day with tests landed and integrated. Estimates do NOT include real-browser end-to-end verification; that's a separate gate per milestone.
>
> **Quality bar:** every milestone ends with `npm test` clean (extending the current 231) + `npm run build` clean + a real-browser smoke on Mac before the milestone is considered shipped.
>
> **Linux-box gate:** M3.5 closure unlocks the first authoritative Linux run (real Ollama integration tier). Each subsequent milestone re-runs the slow tier on Linux as the closing gate.

### Linux-box gate

After M3.5 ships, run on the Linux box:

2. **`OLLAMA_NUM_PARALLEL=1`** — verify slot-stickiness assumption.
3. **All 4 slow-tier integration tests pass on Linux** (`POLARIS_REAL_OLLAMA=1 npm run test:integration:full`).

| 4 | `page.type` + `page.select` + `page.set_checked` (CDP `Input.insertText` + content-script fallback for React-controlled inputs) | 2 | ~200 | 1.5 |

| 6 | Confirmation-gate phase + UI + replay (orchestrator hooks) | 2, 8 | ~250 | 1.5 |
| 7 | SearXNG adapter + multi-engine fallback (DDG → SearXNG → Brave-opt-in) | 3 | ~150 | 0.5 |
| 8 | Embedding-cosine reranker (`rerankBy: 'mxbai'` flag on search tool) | 3 | ~100 | 0.5 |
| 9 | Search caching (IDB-backed, TTL keyed on engine + query) | 3 | ~80 | 0.5 |
| 10 | Composite tool `tab.open_and_extract` (open → wait → extract chained) | 7 | ~60 | 0.5 |
| 11 | ARIA frame traversal (cross-iframe AX tree stitching) | 1 | ~120 | 0.5 |

### Integration tests added

- **Page-stability:** mock CDP `Page.lifecycleEvent`; verify `awaitSettled` resolves only after `networkidle0` AND two AX-tree reads agree.
- **Action surface:** mock CDP `Input.dispatchMouseEvent`; verify `page.click` resolves AX `backendDOMNodeId` → coords → dispatched.
- **React fallback:** content-script-based `page.type` against a fake controlled input that ignores raw `value=`; verify the prototype-setter trick fires correctly.
- **Confirmation gate:** integration test where a destructive tool throws `ConfirmationRequired`; orchestrator transitions to `AWAITING_CONFIRM` phase; user "approves" via test harness; tool resumes.
- **Search triad:** mock fetch; verify primary→fallback→opt-in chain on 5xx / network error / opt-in flag.
- **Reranker:** synthetic 10 results + reference-correct ordering; cosine reranker should produce > 80 % top-3 recall vs. engine-native ranking on a 50-query bench.
- **Composite tool:** mock chrome.tabs + CDP; verify `tab.open_and_extract` saves 2 turns vs. sequential.

### Linux-box gate

- All 4 slow-tier integration tests still passing.
- New: real-browser smoke on Linux — extension loaded, agent run with goal "find the cheapest 4K monitor under $400 from a known retailer." Should: search, open 3 results, extract product records, synthesize, present.
- Telemetry dump: per-Executor-turn p50/p95 latency, per-tool success rate. Recorded in `docs/probes/m4-linux.md`.

### Acceptance criteria

- `page.*` actions land behind an `experimental` flag in settings; default off until M4 closure.
- `npm test` ≥ 290.
- Confirmation gate visible + functional in Mac smoke.

## M5 — Personalization Core + Reasoning Patterns (≈ 10 working days)

### Features

| # | Feature | Stream | LOC | Days |
|---|---|---|---|---|
| 1 | Embedding + cosine helper + `findingEmbeddings` + `archival` IDB stores (DB v1 → v2 schema bump) | 3, 4, 5 | ~200 | 1.5 |
| 2 | `archival.write` / `archival.read` / `archival.search` tools | 5 | ~150 | 1.0 |
| 3 | User profile (Letta-style "core memory" blocks: Address, Diet, Preferences, Persona) — `chrome.storage.local` not IDB | 5 | ~100 + UI | 1.0 |
| 4 | Memory eviction policy (LRU + idle-tick) | 5 | ~80 | 0.5 |
| 5 | Curator role (post-Compactor pass; promotes findings → archival, writes lessons) | 4, 5 | ~200 | 1.5 |
| 6 | Reflexion lessons + retrieval-augmented Planner injection (`lessons` IDB store; embed-on-write; surface top-k in Planner prompt) | 4 | ~250 | 2.0 |
| 7 | Self-verification (Chain-of-Verification before DONE; `Verifier` role at the DONE boundary) | 4 | ~150 | 1.0 |
| 8 | Plan diff replans (replan emits delete/add/modify ops; orchestrator applies) | 4 | ~150 | 1.0 |
| 9 | Cross-source synthesis with citations (Evaluator branch when ≥ 2 findings cite same key; structured `[N]` markers in `finalAnswer`) | 3, 4, 6 | ~150 | 0.5 |

### Integration tests added

- **Archival round-trip:** task A writes "user prefers aisle seats"; task B retrieves via `archival.search("seat preference")` with ≥ 0.7 cosine similarity; surface in Planner prompt.
- **Reflexion:** task A fails on retailer X; lesson written; task B's Planner prompt includes the lesson; task B succeeds.
- **CoVe self-verify:** Executor calls finish; Verifier role contradicts; orchestrator routes to `replan` not `done`. (Reuses mock orchestrator pattern.)
- **Plan-diff:** Planner emits a 5-step plan; Evaluator returns `replan`; Planner emits `{delete: ['s2'], add: [{id: 's6'}]}`; orchestrator applies; new plan has 5 steps but s2 → s6.
- **PII redaction in archival:** task writes "my address is 123 Main St, Springfield"; archival stores redacted form `my address is [ADDRESS]`; cosine retrieval still works.

### Linux-box gate

- M4 slow tier still passes.
- New: 2-task scenario — task A "remember I prefer aisle seats" → archival write → task B "book a flight" → Planner prompt should include the preference. Recorded in `docs/probes/m5-linux.md`.
- Curator latency: end-of-task pass should add < 10 s to a typical run on the P2200 (~200 token prompt).

### Acceptance criteria

- `npm test` ≥ 360 (memory + reasoning unit / integration tests are heavy).
- User profile UI lands in side panel (4 input fields, save/clear).
- Schema bump v1 → v2 has forward-fill migration; existing v1 hot state loads cleanly.
